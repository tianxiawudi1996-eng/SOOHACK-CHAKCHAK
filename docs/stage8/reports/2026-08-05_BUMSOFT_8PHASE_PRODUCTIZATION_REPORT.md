## 1. 경영 요약

수학착착은 브랜드·사용자·제품·디자인·정보 밀도·컴포넌트·캐릭터와 3D/AI 런타임 상세 명세까지 “무엇을 만들 것인가”는 상당히 정리됐다. 그러나 실제 Blender/GLB/Rig/Animation, 운영형 프론트·백엔드·DB, 실사용자 테스트와 Production 배포는 아직 완료되지 않았다.

- 브랜드·제품 정의: 85~90%
- UX·컴포넌트·캐릭터 명세: 75~85%
- 소프트웨어·3D 실제 구현: 20~30%
- 운영 서버·제품화: 5~15%
- 종합 제품화 준비도: 약 40~45%

> 기존 1~8단계는 제품·브랜드 설계 축이고, 프로젝트 폴더→문서→요구사항→설계→개발→테스트→배포→유지보수는 개발 생명주기 축이다.

## 2. 8-Phase 적용

### Phase 1. 프로젝트 기준선·거버넌스
프로젝트 폴더, Git 저장소, docs, harness, 에이전트 지침과 승인 체계를 만든다. GitHub·Harness·기준 폴더는 마련됐으나 SSOT 10종의 로컬/GitHub 동일 바이트, 해시, 승인 로그는 마감이 필요하다.

### Phase 2. 요구사항·제품 범위 동결
브랜드·타깃·제품 약속·학습 5단계는 정리됐다. 첫 출시 단원, P0 포함·제외 기능, 성공·중단 기준과 2D-first/3D-first 결정을 수용 기준으로 동결해야 한다.

### Phase 3. 기능·학습·콘텐츠 설계
35개 컴포넌트, 상태, 말풍선, 캐릭터 행동과 아동 안전 규칙은 상세하다. 콘텐츠 범위, 문제 검증, 힌트, 오개념 교정, 숙련도·반복 규칙을 실행 가능한 요구사항·테스트 계약으로 정규화한다.

### Phase 4. 기술 아키텍처·인프라·DB 설계
JSON/FSM 계약은 있으나 운영형 API·DB·인증·개인정보·배포 환경은 부족하다. 사용자·보호자·동의·세션·응답·숙련도·리포트·Telemetry와 Dev/Staging/Production 책임을 결정한다.

### Phase 5. 화면·컴포넌트·캐릭터 제작 설계
디자인 시스템과 3D 기술 명세는 완료 수준이지만 Storybook, 완전한 Turnaround, Base Mesh, Rig, Motion, GLB, IP 승인은 남아 있다. Gate 1 승인 전 다음 3D Gate로 이동하지 않는다.

### Phase 6. 기능 개발·통합 반복
정적 프로토타입·Harness는 있으나 실제 학습 세션·계정·저장·진단·리포트·캐릭터 런타임은 미완성이다. 2D fallback MVP와 3D 자산 트랙을 병렬 운영한다.

### Phase 7. 통합 테스트·사용자 승인
정적 자동 검사는 일부 통과했지만 실제 브라우저·실기기·스크린리더·저사양·보안·개인정보·학생/부모 테스트는 남아 있다.

### Phase 8. 배포·운영·반복 개선
운영 서버는 미착수다. Development→Staging→Canary→Production, 모니터링, 백업, 롤백을 구축하고 운영 데이터를 Phase 2 요구사항으로 환류한다.

## 4. 제품화 필수 영역

- 제품/학습: MVP 단원, 콘텐츠, 오개념, 평가
- UX/UI: 35개 컴포넌트 코드화, 반응형, 접근성
- Frontend/Backend/DB: 계정, 학습, 기록, 리포트, 데이터 보존
- AI Tutor: 스키마, 수학 검증, 안전 fallback
- 3D: Turnaround, Mesh, Rig, Motion, Runtime
- QA: 기능, 접근성, 성능, 보안, 아동 안전, 사용자 테스트
- Legal/IP: 상표, 캐릭터 유사성, 개인정보
- DevOps: CI/CD, 환경, 모니터링, 롤백

## 5. 권장 전략

**2D 학습 MVP 우선 + 3D 제작 병렬 + Harness 순차 통제**가 가장 현실적이다. 3D 완성을 기다려 학습 제품 전체가 지연되는 것을 막고, 실제 사용성 검증 후 3D의 개입 빈도와 행동을 조정한다.
