# 수학착착 Phase 17 공식 적용 숙달도 설계 v1.0

## 1. Goal Framing

초1~고3 학습자가 공식을 기억하는 데서 끝나지 않고 계산·문장제·단위·표현 관계에 적용하도록 한다. 제품 책임자는 회상과 실제 적용 증거를 분리해 판단할 수 있어야 한다.

## 2. Specification Engineering

12개 학년의 대표 공식 12개에 3문항씩 총 36문항을 제공한다. 각 공식은 계산, 문장제, 단위 또는 표현 추론을 포함한다. 세 문항의 최신 서버채점 결과를 난이도 1·2·3으로 가중하며, 서로 다른 문항 3개와 점수 0.8 이상일 때만 숙달로 판정한다.

## 3. Context Engineering

PostgreSQL 16, Node.js API, 기존 Phase 14 공식 카탈로그, Phase 15 완료 협업 세션, Phase 16 회상 시도를 사용한다. 관련 파일은 migration 0008, 적용 사례 카탈로그, seed 0006, 공식 적용 평가기, curriculum UI다.

## 4. Harness Engineering

정답과 오개념 규칙은 서버에서만 읽는다. 클라이언트는 답·정답 규칙·허용 단위 목록을 받지 않는다. 미완료 협업 또는 회상 시도 없는 적용 평가를 차단하고 학생 소유권·멱등성·최신 문항 증거 집계를 검사한다.

## 5. Prompt Engineering

1. 12개 대표 공식을 교육과정 카탈로그에 연결한다.
2. 공식별 계산·문장제·단위/표현 문제를 세 개 작성한다.
3. 값과 단위를 정규화해 서버에서 채점한다.
4. 대표 오개념 코드를 기록한다.
5. 최신 문항별 결과로 적용 숙달도를 재계산한다.
6. 회상 확인 뒤 적용 UI를 연다.
7. 자동·통합·브라우저·롤백 검사를 실행한다.

성공 기준은 12학년, 12공식, 36문항, 정답 비노출, 선행 회상 차단, 세 문항 증거 기반 숙달 판정이다. 실패 기준은 회상 점수와의 병합, 답 노출, 단일 반복 문항으로 숙달 판정, 단위 무시다.

## 6. Workflow Engineering

`협업 5단계 완료 → 공식 회상 시도 → 적용 문제 3개 → 서버 채점 → 오개념 기록 → 최신 증거 가중 집계 → 복습 예약` 순서로 실행한다.

## 7. Memory Engineering

문항 ID, 값·단위 응답, 결과, 오개념 코드, 문항별 최신 증거, 적용 숙달도와 복습일을 남긴다. 정답의 클라이언트 복제본, 풀이 중 자유서술, 회상·자기보고 점수와 합산한 불명확한 점수는 남기지 않는다.

## 8. Loop Engineering

정답·오답·단위 오류·대표 오개념·멱등 재시도·동일 문항 재도전을 반복한다. 세 문항의 최신 결과가 정확히 집계되고 전체 회귀와 브라우저 여정이 통과하면 Phase 17을 종료한다.
