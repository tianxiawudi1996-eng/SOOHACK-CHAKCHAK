# 수학착착 공식 카탈로그 8개 언어 설계 v1.0

## Goal Framing

초1~고3 학습자는 선택한 언어로 공식 제목, 핵심 설명, 수식 표기와 회상 문제를 읽는다. 한국어 원본을 유지하면서 비한국어 화면의 잔여 한국어를 제거하고, 착착이와 공식이의 협업 세션에도 같은 언어를 고정한다.

## Specification Engineering

- 공식 72개와 로케일 8개를 지원한다.
- 한국어 원본 72행과 비한국어 번역 504행을 최신 리비전으로 조회한다.
- 비한국어 제목·설명·회상 지시문·선택지 표기에는 한글이 남지 않는다.
- 비한국어 자동 생성 번역은 `TRANSLATION_REVIEW_REQUIRED`로 표시하며 사람의 언어 승인을 추정하지 않는다.
- 공개 API는 정답 스키마를 반환하지 않는다.

## Context Engineering

PostgreSQL 16의 `formula_explanation_revision`을 콘텐츠 SSOT로 재사용한다. `title`, `display_notation`, `recall_prompt`를 추가하고 협업 세션에 `content_locale`을 저장한다. Node.js API는 요청 로케일의 최신 리비전을 우선하고 한국어 원본으로 안전하게 대체한다.

## Harness Engineering

정적 감사는 72×7 번역 완전성, 비한국어 한글 잔존, 마이그레이션·롤백 대칭, compose 연결, 공개 응답의 정답 데이터 비노출을 검사한다. 단위 테스트와 실제 PostgreSQL API 통합 테스트를 분리한다.

## Prompt Engineering

1. 72개 공식 제목을 7개 비한국어 로케일에 매핑한다.
2. 설명·회상·캐릭터 전략 템플릿과 언어 중립 수식을 만든다.
3. 리비전 스키마, 시드, 롤백을 작성한다.
4. 카탈로그·협업·회상 API를 로케일 인식형으로 수정한다.
5. 자동 QA를 통과시키되 언어 전문가 승인은 대기 상태로 남긴다.

## Workflow Engineering

`원본 감사 → 번역·표기 생성 → DB 리비전 적재 → API 폴백 → UI 연결 → 단위·통합 검사 → 롤백·재적용 → 수동 언어 검토 대기` 순서로 수행한다.

## Memory Engineering

공식 semantic key, 로케일, 리비전, 검증 상태, 공식 출처와 자동 검사 결과를 남긴다. 정답 스키마, 비밀값, 생성 도구 메타데이터와 허위 수동 승인 기록은 클라이언트·mock·증적에 남기지 않는다.

## Loop Engineering

72개 공식과 7개 번역 로케일을 전수 순회한다. 빈 필드나 한글 잔존이 하나라도 있으면 실패한다. PostgreSQL 수량 576행, API 8/8, 회상 선택지 4/4, 회귀 테스트와 롤백 복구가 모두 통과하면 구현을 종료하고 언어 검토로 인계한다.
