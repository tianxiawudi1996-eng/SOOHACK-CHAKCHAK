# Phase 25 학습 품질 KPI·개인정보 최소화 분석 설계 v1.0

## 의사결정과 사용자

제품 책임자와 학습 설계자는 학습자가 공식을 끝까지 학습하고, 적용하고, 나중에 회상하는지를 판단해야 한다. 학습자는 본인 범위의 집계 결과만 조회한다. 이 지표는 순위화·광고·프로파일링에 사용하지 않는다.

## 검토한 근거와 원천

권위 있는 원천은 PostgreSQL의 `formula_learning_session`, `student_formula_application_progress`, `formula_recall_attempt`, `formula_learning_response`, `collaboration_phase_evidence`다. 별도 추적 쿠키나 원답 복제 테이블을 만들지 않는다. 현재 데이터는 로컬 합성 학습 흐름이므로 운영 목표 확정 근거로 사용하지 않는다.

## 권장 KPI

| 구분 | 지표 | 계산 | 의사결정 | 임시 목표 |
|---|---|---|---|---:|
| Primary | 학습 완료율 | 완료 공식 세션 / 시작 공식 세션 | 시작 후 이탈·흐름 마찰 조사 | 0.80 |
| Primary | 공식 적용 숙달률 | 숙달 공식 / 적용 평가 공식 | 설명·적용 문제 난이도 조정 | 0.80 |
| Primary | 지속 회상률 | 회상 정답 / 회상 시도 | 복습 간격·회상 문항 개선 | 0.75 |
| Driver | 독립 응답률 | 힌트 없는 공식 응답 / 공식 응답 | 힌트 단계와 착착이 개입 강도 조정 | 0.50 |
| Driver | 협업 단계 통과율 | PASS 단계 / 기록 단계 | 착착이·공식이 역할과 지원 단계 조정 | 0.60 |

목표는 `PROVISIONAL_NO_FIELD_BASELINE`이다. 운영에서 학생 최소 50명·완료 세션 최소 200건과 4주 관측이 확보된 뒤 분포와 학년별 차이를 검토하여 확정한다.

## 데이터 충분성·가드레일

학생별로 완료 세션·적용 평가·회상 시도가 각각 3건 이상일 때만 `data_sufficient=true`다. 분모가 0이면 0으로 오해하지 않도록 비율을 `null`로 반환한다. 지표 상승이 정답 노출·과도한 힌트·쉬운 문항 편향으로 만들어지지 않도록 독립 응답률과 협업 통과율을 함께 본다.

## 개인정보·권한

- API: `GET /api/v1/students/{student_id}/learning-quality`
- 인증된 학생 본인의 소유 범위에서만 조회한다.
- 응답에는 학생·사용자 ID, 원답, 문제 본문, 토큰, 이메일, IP를 넣지 않는다.
- 텔레메트리 속성은 이벤트별 허용목록의 평면 기본형 값만 허용한다.
- 집계 API는 기존 원천을 읽기만 하며 새 개인정보·행동 원문을 저장하지 않는다.

## 한계와 열린 질문

현재는 로컬 합성 데이터만 있어 목표 신뢰도가 낮다. 운영 배포 후 학년별 최소 표본, 장기 회상 관측 기간, 교사·학부모 보고 범위, 삭제·동의 정책을 승인해야 한다. 코호트 비교와 실험 통계는 최소 집단 크기·동의·비식별화가 확정되기 전까지 제외한다.
