# 보안·운영 기준선 v1.0

## 비밀값

- `.env.example`에는 키 이름과 설명만 둔다.
- 실제 비밀값은 환경별 관리 서비스에 저장하고 저장소·로그·브라우저 번들에 넣지 않는다.
- 유출 의심 시 폐기·교체·영향 조사 순서를 따른다.

## 아동 데이터

- 수집 목적이 없는 필드는 만들지 않는다.
- 학생·학부모 연결과 동의를 서버에서 검증한다.
- 보존·삭제·내보내기 절차를 DB 설계와 API 계약에 연결한다.
- 분석 이벤트는 익명 세션과 허용 필드만 사용한다.

## 릴리스

1. 변경 범위와 요구사항 ID 확인
2. 린트·타입·단위·통합·국제화 검사
3. 마이그레이션 forward/rollback 검사
4. 스테이징 배포와 health check
5. 8개 로케일 smoke와 접근성 검사
6. 수동 승인
7. 운영 배포와 관찰
8. 실패 임계치 초과 시 롤백

## 초기 경보 기준

- API 5xx 비율 5분간 2% 초과
- 핵심 API p95 2초 초과
- DB 연결 사용률 80% 초과
- 번역 fallback 비율 1% 초과
- 큐 최고 지연 5분 초과
- 배포 후 진단·학습 완료 실패율 기준선 대비 2배

실제 트래픽 기준선 확보 후 임계치를 조정하고 변경 근거를 기록한다.
