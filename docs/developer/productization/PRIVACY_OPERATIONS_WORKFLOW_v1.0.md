# 수학착착 개인정보 운영자 처리 흐름 v1.0

## 목표

학생의 개인정보 권리 요청을 운영자가 안전하게 배정받아 신원 확인, 검토, 승인 또는 반려할 수 있게 한다. 운영 검토와 실제 데이터 이행은 분리한다.

## 요구사항

| ID | 요구사항 | 인수 기준 |
|---|---|---|
| PRIV-27-01 | 운영 큐 조회 | 활성 `ADMIN`만 처리 대상 요청을 조회하며 직접 식별자는 반환하지 않는다. |
| PRIV-27-02 | 단일 담당자 배정 | 상태 전이 시 담당자를 원자적으로 배정하고 다른 담당자의 동시 처리를 409로 차단한다. |
| PRIV-27-03 | 신원 증적 | `IDENTITY_VERIFIED` 전이에 내부 증적 참조와 SHA-256을 요구한다. |
| PRIV-27-04 | 결정 사유 | 승인·반려에 구조화된 사유 코드를 요구하고 별도 결정 테이블에 기록한다. |
| PRIV-27-05 | 상태 이력 | 모든 전이를 기존 `privacy_request_event`에 동일 트랜잭션으로 기록한다. |
| PRIV-27-06 | 이행 차단 | 실제 이행 실행기가 없는 동안 `COMPLETED` 전이는 항상 차단한다. |

## 상태와 데이터 흐름

```text
로컬 합성 ADMIN 세션
→ 운영 큐 조회
→ 요청 행 잠금
→ 담당자 충돌 확인
→ 증적·결정·상태 이력 원자 저장
→ 식별자를 제거한 운영 결과

RECEIVED → IDENTITY_VERIFIED → IN_REVIEW → APPROVED | REJECTED
APPROVED → COMPLETED  [현재 강제 차단]
```

## API

- `POST /api/v1/local-demo/privacy-operator/session`: 로컬 데모가 활성화된 경우에만 합성 운영자 토큰 발급
- `GET /api/v1/privacy-operations/requests`: 처리 대상 요청 최대 100건
- `POST /api/v1/privacy-operations/requests/{id}/transition`: 상태 전이·증적·결정 기록

운영 전이 쓰기는 `Idempotency-Key`가 필요하다. 학생 토큰은 운영 API에서 403을 받는다. 로컬 데모가 꺼진 환경에서 합성 운영자 세션 발급 경로는 404다.

## 증적과 개인정보 최소화

- 증적 원문 대신 내부 참조 ID와 SHA-256만 저장한다.
- 큐 응답에는 요청자·정보주체·학생·담당자의 내부 식별자를 포함하지 않는다.
- 답안, 문제 원문, 연락처, 토큰, 신분증 원문을 DB와 로그에 저장하지 않는다.
- 실제 삭제·정정·내보내기·동의 철회 성공을 추정하지 않는다.

## 외부 차단

운영 적용에는 관리형 신원 공급자, 최소 권한 관리자 그룹, 개인정보 보호책임자 정책, 증적 보관소, 이중 승인과 감사 조회가 필요하다. 준비 전 상태는 `BLOCKED_EXTERNAL_IDENTITY_POLICY`다.
