# 수학착착 Phase 16 공식 회상 확인 설계 v1.0

## 1. Goal Framing

- 사용자: 협업 학습을 마친 초1~고3 학습자
- 변화: 72개 공식 각각에 채점 가능한 빠른 확인 문제가 생기고 결과가 공식별 회상 점수로 축적된다.

## 2. Specification Engineering

공식 72개에 1문항씩, 문항당 선택지 4개가 존재하고 협업 5단계 완료 후에만 응답할 수 있어야 한다. 정답 스키마는 서버 밖으로 노출하지 않는다. 결과는 `recall_score`이며 실제 계산·적용 숙달도로 표시하지 않는다.

## 3. Context Engineering

PostgreSQL 16, Node.js API, 기존 정확 일치 채점기, Phase 14 공식 카탈로그, Phase 15 완료 세션을 사용한다.

## 4. Harness Engineering

결정적 시드 생성기, 정답 비노출 감사, 학생 소유권, 완료 세션·공식 일치, 멱등성, DB 제약으로 통제한다.

## 5. Prompt Engineering

1. 공식 회상 문항·시도·진행 테이블을 만든다.
2. 학년별 공식 표현을 이용해 72개 4지선다 문항을 결정적으로 생성한다.
3. 정답 없는 조회 API와 서버 채점 API를 구현한다.
4. 협업 완료 화면에 문제와 결과를 연결한다.
5. 단위·통합·브라우저·롤백 검증을 수행한다.

## 6. Workflow Engineering

`협업 5단계 완료 → 회상 문제 조회 → 선택 제출 → 서버 채점 → recall_score·복습일 갱신`

## 7. Memory Engineering

문항 ID, 선택값, 정오 결과, 시도 시간, 회상 점수, 복습일만 저장한다. 정답 스키마·개인정보·자유 텍스트는 클라이언트에 남기지 않는다.

## 8. Loop Engineering

72개 문항 생성, 선택지 4개, 정답 1개를 반복 감사한다. 정답 노출·공식 불일치·미완료 세션 응답을 실패로 처리한다. 전체 회귀와 브라우저 채점이 통과하면 종료한다.
