# 수학착착 Phase 15 협업 학습 런타임 설계 v1.0

## 1. Goal Framing

- 사용자: 초1~고3 학습자와 학습 진행을 확인하는 제품 책임자
- 변화: 착착이·공식이 협업 계획이 실제 5단계 세션으로 실행되고 지원 필요 신호와 완료 기록이 PostgreSQL에 남는다.

## 2. Specification Engineering

완료 상태는 세션 생성, 1~5단계 순차 증거 저장, 중복 단계 차단, 완료 점수 계산, 다음 복습일 저장이 동일 학생 소유권 안에서 동작하는 상태다. 이 점수는 구조화된 자기보고 기반 협업 진행 점수이며 수학 정답 숙달도로 표시하지 않는다.

## 3. Context Engineering

- 기술: Node.js HTTP API, PostgreSQL 16, 정적 HTML/CSS/JavaScript
- 입력: Phase 14 공식 카탈로그와 `pet-collab-v1` 정책
- 관련 파일: migration 0006, `collaboration-runtime.mjs`, curriculum API/UI

## 4. Harness Engineering

AI는 자유 텍스트, 개인정보, 정답으로 오인되는 임의 값을 저장하지 않는다. 단계 번호·허용 신호·소유권·멱등성·완료 조건·롤백 대칭성을 자동 감사한다.

## 5. Prompt Engineering

1. 단계 증거와 공식별 진행 집계 스키마를 만든다.
2. 단계별 허용 신호와 점수 계산을 순수 함수로 구현한다.
3. 조회·증거 제출·완료 API를 소유권과 멱등성 통제 안에서 구현한다.
4. UI에서 현재 단계, 두 선택지, 완료 결과를 제공한다.
5. 단위·통합·브라우저·PostgreSQL 롤백 검증을 통과한다.

성공 기준은 단계 5/5, 중복 차단, 완료 기록 1/1, 화면 진행 5/5다. 순서 건너뛰기, 타인 세션 접근, 자유 텍스트 저장, 미완료 세션 완료는 실패다.

## 6. Workflow Engineering

`협업 세션 생성 → 준비 확인 → 개념 연결 → 공식 구성 → 적용 확인 → 검산·회고 → 완료 점수·복습일 저장`

## 7. Memory Engineering

남길 것은 공식 ID, 단계 번호, 구조화 신호, 지원 여부, 힌트 수준, 소요 시간, 완료 점수, 다음 복습일이다. 자유 텍스트, 정답 원문, 개인정보, 브라우저 토큰은 남기지 않는다.

## 8. Loop Engineering

보충·기본·도전 경로별로 5단계를 반복 검증한다. 단계 중복·순서 오류·소유권 위반을 주입하고 차단되는지 확인한다. 전체 회귀 검사와 수동 브라우저 여정이 통과하면 Phase 15를 종료한다.
