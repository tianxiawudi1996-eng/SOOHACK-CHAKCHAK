# AI 튜터 확장 스테이징 관찰 준비 런북 v1.0

## 목적

Phase 52의 8/8 canary 통과 및 제품 책임자 승인 이후에만 내부 QA 합성 관찰을 준비한다. 이 문서는 실행 절차가 아니라 실행 전 handoff 계약이다.

## 진입 조건

1. Phase 52 상태가 `CANARY_ACCEPTED_FOR_EXTENDED_STAGING`이다.
2. Phase 52 대장의 SHA-256이 Phase 53 대장과 일치한다.
3. 최대 24시간의 스테이징 관찰 창 참조와 시작·종료 시각이 있다.
4. 단일 제품 책임자의 명시적 승인 참조와 승인 시각이 있다.
5. kill switch와 규칙 기반 fallback을 사용할 수 있다.

## 관찰 계획

- 대상: 내부 QA 합성 시나리오만 사용
- 로케일: `ko`, `zh-CN`, `ja`, `en`, `es`, `fr`, `it`, `ru`
- 표본: 로케일당 10건, 총 80건
- 동시성: 1
- 재시도: 요청당 0회
- 저장: 참조·정량 지표만 저장하며 입력·출력 원문과 학생 식별자는 저장하지 않는다.

## 프로젝트 임계치

스키마·역할 분리·로케일 성공률은 100%, 안전·정답 유출·개인정보·버전 불일치·예산 초과·kill switch 실패는 0건이다. provider 오류율은 5% 이하, fallback 비율은 10% 이하, p95 지연은 1,500ms 이하로 둔다. 이 수치는 수학착착의 보수적 프로젝트 정책이며 OpenAI가 의무화한 수치가 아니다.

## 중단과 복구

hard gate 위반이 한 건이라도 생기면 새 요청을 중단하고 규칙 기반 튜터로 복귀한다. kill switch 재무장과 rollback 증거는 Phase 54 결과 대장에서 참조로 수집한다. 원문이나 secret을 증거에 넣지 않는다.

## 현재 상태

Phase 52 실제 결과 0/8, 관찰 창 `PENDING_EXTERNAL`, 제품 책임자 승인 `NOT_REQUESTED`, 관찰 0건이다. 따라서 Phase 53은 `BLOCKED_EXTERNAL`이며 어떤 dispatch도 허가하지 않는다.
