# 수학착착 Phase 22 — 키보드·초점·대비·스크린리더 접근성 실행 메타프롬프트 v1.0

## Goal Framing

학생·보호자가 키보드 또는 스크린리더로 랜딩, 진단, 공식 수업과 교육과정 협업 흐름을 끊김 없이 사용할 수 있게 한다.

## Specification Engineering

완료 상태는 건너뛰기 링크 4/4, 키보드 초점 계약 4/4, 동적 전환 초점 대상 7/7, 핵심 대비 조합 12/12, reduced-motion 4/4, 키보드 함정 0건이다. 자동 QA와 제품 책임자 수동 승인을 분리한다.

## Context Engineering

입력은 Phase 21의 8언어 접근성 메시지와 네 스테이징 화면이다. 구현 파일은 공통 접근성 CSS와 진단·수업·교육과정 HTML/JS이며, 출력은 Phase 22 정적 검사기·단위/통합 테스트·QA 증거·보고서다.

## Harness Engineering

허용 도구는 HTML/CSS/JavaScript 편집, Node 테스트, 로컬 Docker PostgreSQL/API/Web, 인앱 브라우저와 Git이다. 브라우저 저장정보와 민감정보를 읽지 않으며 수동 승인 결과를 추정하지 않는다.

## Prompt Engineering

1. 현재 Tab 순서와 초점 표시를 감사한다.
2. 모든 `main`을 건너뛰기 대상으로 만든다.
3. 비동기 화면 전환 후 의미 있는 제목으로 초점을 이동한다.
4. 공통 고대비 초점 링과 reduced-motion 대체를 적용한다.
5. 핵심 색상 조합을 계산 검증한다.
6. 단위·통합·브라우저 검사를 실행한다.
7. 수동 검토 패킷을 준비하되 승인으로 계산하지 않는다.

## Workflow Engineering

`감사 → 계약 → 구현 → 단위 검사 → 스테이징 → 통합 검사 → 브라우저 키보드 검사 → 수동 검토 대기 → 보고` 순서로 실행한다.

## Memory Engineering

검사 기준, 수정된 초점 이동, 대비 결과, 테스트 증거와 수동 검토 상태를 남긴다. 임시 DOM 스냅샷, 승인 추정, 민감한 세션 토큰과 개인 데이터는 제거한다.

## Loop Engineering

순방향·역방향 Tab, Enter 활성화, 진단·수업·협업 전환을 반복한다. 초점 소실, 키보드 함정, 3:1 미만 초점 표시, 4.5:1 미만 일반 텍스트 또는 모션 축소 위반이 있으면 해당 화면을 수정하고 전체 회귀검사를 다시 실행한다.
