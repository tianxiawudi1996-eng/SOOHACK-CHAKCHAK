# 수학착착 Phase 21 — 접근성 문구·언어별 검토 패킷 실행 메타프롬프트 v1.0

## Goal Framing

선택 언어로 수학착착을 사용하는 학습자가 시각 표시와 화면 읽기 도구에서 같은 의미를 이해하도록 한다.

## Specification Engineering

네 핵심 화면, 31개 접근성 키, 8개 언어, 수동 검토 패킷 7개가 완전해야 한다. 자동 QA는 7개 비한국어 언어 승인을 대신하지 않는다.

## Context Engineering

입력은 Phase 19~20 번역과 네 클라이언트 화면이다. 출력은 접근성 SSOT, 화면 연결, 스테이징 산출물, 검토 패킷과 Phase 21 증적이다.

## Harness Engineering

Node 테스트, 정적 감사, 로컬 Docker 스테이징과 브라우저만 사용한다. 외부 메시지 발송, 리뷰어 정보 추정, 운영 배포는 하지 않는다.

## Prompt Engineering

1. 하드코딩 접근성 문구를 찾는다. 2. 8개 언어 공통 키를 만든다. 3. 텍스트·ARIA·ALT를 연결한다. 4. 진행률 의미를 보강한다. 5. 7개 검토 패킷을 고정 해시로 생성한다. 6. 자동·브라우저 검사를 실행한다.

## Workflow Engineering

`감사 → 명세 → 구현 → 패킷 생성 → 단위 → 정적 → 빌드 → 통합 → 브라우저 → 보고` 순서로 실행한다.

## Memory Engineering

키 범위, 패킷 ID와 소스 해시, 테스트 결과, 수동 승인 0/7을 남긴다. 추정 승인과 개인 연락처는 제거한다.

## Loop Engineering

4×8 화면 조합과 7개 패킷을 반복 검사한다. 접근성 이름 누락 또는 혼합 언어가 있으면 수정하고 전체 회귀를 다시 실행한다. 자동 QA PASS와 수동 검토 대기가 확인되면 종료한다.
