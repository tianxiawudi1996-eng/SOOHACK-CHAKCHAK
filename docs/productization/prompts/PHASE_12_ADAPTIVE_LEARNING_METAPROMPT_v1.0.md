# 수학착착 Phase 12 — 진단 기반 적응형 학습 실행 메타프롬프트 v1.0

## 1. Goal Framing

- 사용자: 초등 수학 학습자, 보호자, 제품 책임자
- 달라져야 하는 것: 진단 결과가 실제 학습 난이도·힌트 깊이·복습 시점 선택으로 연결된다.

## 2. Specification Engineering

완료 상태는 진단 정확도에 따라 `REMEDIATE | CORE | EXTEND`를 서버가 결정하고, 결정 근거·학습 경로·공식 학습 후 숙달도를 PostgreSQL에 저장하며 최신 추천 API로 조회할 수 있는 상태다.

성공 기준:

- 적응형 경로 3/3
- 임계값 0.5·0.8 경계 검사
- 진단 완료와 결정 저장이 한 트랜잭션
- 경로별 시작 힌트·목표 난이도 고정
- 공식 학습 완료 후 주제 숙달도 저장
- 학생 소유권과 idempotency 유지
- 원문 답안·문제·비밀정보의 결정 레코드 복사 0건

실패 기준:

- 클라이언트가 경로를 임의 결정
- 진단 완료됐지만 결정 또는 학습 경로가 누락
- 임계값 경계에서 비결정적 결과
- 다른 학생의 추천 조회 허용

## 3. Context Engineering

- Node.js ESM, PostgreSQL 16, REST JSON
- 입력: Phase 10 공식 학습 엔진, Phase 11 학생 UI, 기존 진단 3문항
- 구현: 적응형 경로 엔진, migration 0003, 저장소·API 확장
- 출력: 설계서, 계약, 단위·통합 테스트, QA 증거, Phase 보고서

## 4. Harness Engineering

허용 도구는 코드·SQL 편집, Node 테스트, Docker Compose PostgreSQL, 정적 검증기, 브라우저다. 실제 운영 데이터·외부 배포·외부 AI 호출은 사용하지 않는다. 로컬 합성 학생 데이터만 사용한다.

## 5. Prompt Engineering

1. 경로 선택 순수 함수와 경계 단위테스트를 작성한다.
2. 적응형 결정·주제 숙달도 migration과 rollback을 작성한다.
3. 진단 완료 트랜잭션에 경로 결정을 연결한다.
4. 최신 추천 조회와 공식 완료 숙달도 저장을 구현한다.
5. 정적 감사기와 PostgreSQL 통합 테스트를 작성한다.
6. 전체 제품화 회귀 테스트 후 증거·상태·보고서를 갱신한다.

## 6. Workflow Engineering

`계약 → 순수 함수 → DB → 저장소 → API → 단위테스트 → PostgreSQL 통합테스트 → 전체 회귀 → 보고`

## 7. Memory Engineering

경로 임계값, 알고리즘 버전, 경로별 학습 설정, 진단 요약, 숙달도와 테스트 결과를 남긴다. 원문 응답, 임시 토큰, 컨테이너 내부 비밀값은 남기지 않는다.

## 8. Loop Engineering

보충·기본·도전 시나리오를 매 실행마다 새 진단 세션으로 반복한다. 실패 시 함수·제약·트랜잭션 중 원인을 분리해 수정한다. 자동 QA와 실제 PostgreSQL 통합 테스트가 모두 통과하면 종료한다.
