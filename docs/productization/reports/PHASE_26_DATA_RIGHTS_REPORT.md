# 수학착착 Phase 26 학생 개인정보 권리 요청 보고서

## 결과

학생 본인이 열람·내보내기·정정·삭제·처리 제한·동의 철회 요청을 접수하고, 본인 요청 목록·상세·상태 이력을 조회하며 초기 요청을 취소할 수 있게 했다. 삭제 요청은 실제 학습 데이터 삭제와 분리했고 내부 사용자·학생 식별자는 공개 응답에서 제거했다.

자동 검증 상태는 `AUTO_VERIFIED_LOCAL_DATA_RIGHTS`다. 이는 로컬 합성 학생 흐름의 기술 검증이며 법률 준수 인증 또는 운영 승인 결과가 아니다.

## 산출물

- PostgreSQL: `privacy_request`, `privacy_request_event`, 인덱스 3개, 전진·롤백 마이그레이션
- 도메인: 요청 유형 6개, 상태 전이, 취소 정책, 공개 매핑, 외부 차단 경계
- API: 접수·목록·상세·취소 4개 엔드포인트
- 문서: 요구사항·데이터 흐름·공식 참고·실행 메타프롬프트·QA 증거

| 검사 | 결과 |

| 마이그레이션 전진→롤백→재적용 | PASS |
| 재적용 후 DB 요청/이력 | 1/2 정상 저장 |

전체 통합 첫 실행은 `TEST_SESSION_HMAC_SECRET`이 없어 3개 테스트 파일이 테스트 전 중단됐다. 코드 수정 없이 로컬 합성 세션 키를 명시해 재실행했고 17/17이 통과했다.

## 사실·가정·미결정

- 사실: 학생 세션 소유권, 멱등성, PostgreSQL 트랜잭션, 요청 이력, 취소 역조건이 로컬에서 검증됐다.
- 가정: `privacy-rights-v1`은 제품 내부 정책 버전이며 법정 처리 기한이나 거절 사유를 확정하지 않는다.
- 미결정: 보호자 신원·대리권, 운영자 승인 역할, 실제 내보내기·정정·삭제 이행, 법적 보존 분리, 통지·이의제기 절차다.

## 차단 조건과 다음 Phase

보호자 요청은 관리형 신원 공급자, 활성 학부모 연결 재검증, 대리권·동의 정책이 없으므로 `BLOCKED_EXTERNAL_IDENTITY_POLICY`다. 자동 삭제와 동의 변경도 승인된 운영 워크플로 전에는 수행하지 않는다.

다음 Phase 27은 자동 삭제가 아니라 개인정보 운영자 처리 큐·결정 사유·이행 증적 계약을 설계하고, 실제 삭제·내보내기 실행기는 별도 수동 승인 게이트 뒤에 둔다.
