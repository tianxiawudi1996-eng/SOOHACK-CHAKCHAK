# 수학착착 Phase 18 공식 적용 문제 전수 확장·8개 언어 완료 보고서

## Goal Framing

초1~고3 학습자가 72개 공식 모두에서 적용 문제를 풀 수 있도록 대표 공식 12개 범위를 전체 공식으로 확장했다. 문제 지시문·입력 레이블·채점 피드백을 한국어·중국어·일본어·영어·스페인어·프랑스어·이탈리아어·러시아어로 제공한다.

## Specification Engineering

- 공식: 72/72
- 신규 확장: 60/60
- 문제: 216/216, 공식별 난이도 1~3
- 번역: 1,728/1,728
- 평가 유형: 계산·문장제·단위 추론·표현 추론 4/4
- 정답·허용 단위·오개념 규칙 공개 노출: 0

## Context Engineering

교육과정 기준은 교육부 고시 제2022-33호 별책 8이다. PostgreSQL 16의 문제 항목과 번역 테이블, Node.js 서버 채점 API, 정적 학생 UI를 연결했다. 기존 협업 5단계와 공식 회상 완료를 적용 문제의 진입 조건으로 유지했다.

## Harness Engineering

Postgres 모범 사례에 따라 번역은 JSON 덩어리가 아닌 관계형 행으로 분리했고 외래 키 선두 열을 기본 키로 인덱싱했다. 216개 문제와 로케일별 216개 번역을 배치 삽입한다. 공개 API는 문제·레이블·난이도·단위 필요 여부만 반환한다.

## Prompt Engineering

72개 공식 키를 전수 대조하고 각 공식에 난이도 1·2·3 문제를 작성했다. 수학식은 로케일 중립 정본으로 유지하고 문제 지시문과 레이블을 8개 언어 템플릿으로 생성했다. 단위가 필요한 31개 문제에서만 단위 입력을 노출하고 필수화했다.

## Workflow Engineering

`정본 감사 → 문제 은행 작성 → 번역 생성 → PostgreSQL 마이그레이션·시드 → API 로케일 조회 → UI 연결 → 롤백·복구 → 브라우저 검토`를 완료했다.

## Memory Engineering

문제 정본, 정답 규칙, 로케일 템플릿, 생성 SQL, QA 증거와 콘텐츠 버전을 저장했다. 정답 데이터는 브라우저 산출물에 포함하지 않았고 컨셉아트·HTML mock에 개발 메타데이터를 추가하지 않았다.

## Loop Engineering

단위 테스트 42/42, 정적 감사, PostgreSQL 수량 검사, 신규 공식 8개 로케일 API, 기존 대표 공식 회귀, 마이그레이션 롤백·재적용, 중국어 브라우저의 일반·단위 문제, 전체 제품화 회귀와 통합 여정 10/10을 반복 검증했다. 모두 통과하여 Phase 18을 `VERIFIED`로 종료한다.

## 검증 결과

- PostgreSQL: 항목 216, 공식 72, 번역 1,728, 로케일 8
- API: 신규 공식 문제 3/3 × 로케일 8/8, 서버 채점·숙달 100%
- 회귀: Phase 17 대표 공식 적용 경로 통과
- 브라우저: 중국어 문제·레이블, 단위 필드 숨김/필수 전환, 정답 비노출 통과
- 롤백: 번역 테이블·단위 플래그만 제거 후 마이그레이션과 시드 복원 통과
