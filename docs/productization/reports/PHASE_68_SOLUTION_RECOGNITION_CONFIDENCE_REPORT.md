# Phase 68 풀이 인식 신뢰도·수동 대체 경로 보고서

## 결과

수동 수식 입력, 신뢰도 판정, PostgreSQL 최소 저장, 교사 검토 큐, 학생 소유권, 멱등성 API까지 로컬 플랫폼 구현을 완료했다. 그러나 승인된 OCR 공급자와 실제 학년·문항 유형별 필기·사진 정확도 벤치마크가 없으므로 D80-03과 80점 제품 요건은 아직 완료가 아니다.

```text
manual_text_path = PASS_LOCAL
image_input = FAIL_CLOSED_TO_MANUAL_ENTRY
ocr_provider = NOT_CONFIGURED
accuracy_benchmark = NOT_RUN
D80-03 = BLOCKED_EXTERNAL
market_score_80_confirmed = false
```

## 구현

- `MANUAL_TEXT`, `HANDWRITING_IMAGE`, `CAMERA_IMAGE` 입력 계약
- 학생 확인, 교사 검토, 수동 입력, 거부의 네 가지 결정
- 클라이언트가 보낸 OCR 공급자 인증·신뢰도 값을 신뢰하지 않는 서버 통제
- 원본 이미지와 인식 수식 미저장, 정규화된 후보의 SHA-256만 저장
- 자동 채점은 DB 제약조건과 응답 계약 모두에서 금지
- 수학 일관성 또는 단계 연속성 미달 시 교사 검토 큐 자동 생성
- 착착이는 질문·안심, 공식이는 수학 구조 검증 역할 유지

## PostgreSQL 설계 영향

PostgreSQL 모범 사례에 따라 FK, CHECK, 유일 제약, 학생별 시간순 인덱스, 대기열 부분 인덱스, 후보 해시 JSONB 인덱스를 적용했다. 저장 트랜잭션에는 캡처·평가·멱등성·메타데이터 감사 로그가 함께 포함된다. 이 설계는 원문 학생 답안을 보관하지 않으면서 상태 조회와 교사 대기열 운영을 지원한다.

## 남은 외부 작업

1. 미성년자 데이터 처리 조건을 충족하는 OCR 공급자 승인
2. 원본 이미지의 동의·보존·삭제·암호화 정책과 객체 저장소
3. 초1~고3, 수식·도형·서술형·다단계 풀이별 동의된 벤치마크 데이터
4. 정확도·오탐·누락·신뢰도 보정 기준과 수학 전문가 검토
5. 실제 사진 업로드 UI, 접근성, 모바일 카메라, 현장 E2E

다음 로컬 Phase는 69이며, 실제 커리큘럼·문항·해설 완성도와 학습 경로 E2E를 강화한다. OCR 증거가 공급되기 전까지 이미지 입력은 수동 입력 대체를 유지한다.
