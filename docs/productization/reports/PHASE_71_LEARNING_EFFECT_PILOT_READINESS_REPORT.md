# Phase 71 학습효과 파일럿 준비도 보고서

## 결과

D80-06의 최소 100명·8~12주 비교 파일럿을 실행하기 위한 로컬 기술 기반을 구현했다. 사전등록 분석계획, KPI 계층, PostgreSQL 프로토콜·코호트·가명 참여자·측정·독립 분석 결과 구조, 관리자 준비도 API가 연결되었다. 로컬 시드는 2개 코호트와 8개 KPI 정의만 포함하며 실제 참여자·동의·측정·효과 결과는 모두 0건이다.

현재 상태는 `LOCAL_PILOT_READINESS_PLATFORM_PASS_ACTUAL_PILOT_BLOCKED_EXTERNAL`이다. 이는 파일럿 실행 준비용 소프트웨어가 자동 검증을 통과했다는 뜻이며, 학습효과·대치동 적합성·시장 점수 80점을 입증했다는 뜻이 아니다.

## 목표와 범위

- 사용자: 제품 책임자, 연구 운영 책임자, 개인정보 책임자, 독립 통계 검토자
- 문제: 제품 기능 테스트만으로 실제 학습효과를 주장할 수 없고, 결과 확인 전에 표본·기간·KPI·분석 방법을 고정할 기반이 없었다.
- 변화: 현장 자료를 안전하게 접수하면 사전등록 조건과 일치하는지 관리자 API와 DB 제약으로 감사할 수 있다.
- 제외: 학생 모집, 보호자 동의 취득, 코호트 배정, 실제 8~12주 운영, 독립 분석, 효과 승인

## KPI 설계

핵심 KPI는 사전 점수를 보정한 사후 성취도 차이와 유지 성취도 차이 2개다. 학습계획 완료율과 독립 응답률은 원인 파악용 동인 지표이며, 중도탈락률 차이·핵심 결과 결측률·학습 이상사건률·중대 개인정보 사건 수는 가드레일이다. 동인 지표 개선만으로 효과를 선언하지 않는다. 최소 효과크기 임계값은 현장 기준선과 독립 통계 검토 없이 임의로 만들지 않았다.

## 데이터·권한 통제

- 참여자는 이름·이메일·전화번호 대신 SHA-256 가명 키만 저장한다.
- 동의 원문 대신 승인된 외부 증거 참조만 저장한다.
- 파일럿 측정 테이블에 원문 답안과 문제 원문 필드는 없다.
- 프로토콜 잠금 이후 최소 표본, 기간, 배정 방법, 분석계획 해시, 책임 참조를 DB 트리거로 변경할 수 없다.
- 복합 외래키가 서로 다른 프로토콜의 코호트·참여자·KPI 측정이 섞이는 것을 차단한다.
- 관리자 준비도 API는 ADMIN만 접근할 수 있고 학생 접근은 403이다.
- 준비도 로직은 입력 수가 등록 인원을 초과하면 등록 인원으로 제한하며, 모든 외부 증거가 접수되어도 학습효과를 자동 승인하지 않는다.
