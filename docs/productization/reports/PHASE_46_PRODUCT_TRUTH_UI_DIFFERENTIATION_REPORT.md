# Phase 46 — 제품 진실성·UI 차별화 레드팀 개선 보고서

## 목표

사용자가 지적한 평범한 화면 구성과 부족한 AI·자동화 기능 표현을 시니어 제품·개발 관점에서 전수 점검하고, 실제 구현 수준을 과장하지 않는 제품 기준선과 수학착착 고유의 화면 언어를 확립한다.

## 사실·가정·미결정

- 사실: 기능 계약 15개 중 운영 준비 완료 기능은 `0/15`다.
- 사실: 현재 검증된 범위는 로컬 규칙 엔진, 정적 학습 흐름, 승인된 캐릭터 자산과 스테이징 UI다.
- 사실: 실제 생성형 AI 튜터, 자동 학습계획 생성, 보호자 인증·리포트, 운영 관측성은 아직 운영 연결되지 않았다.
- 가정: 다음 제품화 세로 조각은 분수 학습을 대상으로 한 AI 튜터 커널이 가장 높은 사용자 가치를 만든다.
- 미결정: AI 모델·운영 계정·비용 한도·보호자 동의 정책·운영 배포 승인은 외부 결정이 필요하다.

## 변경 산출물

1. `developer/contracts/feature-implementation.json`
   - 15개 기능을 실제 증거 수준에 따라 재분류했다.
   - `production_ready`는 명시적으로 `0/15`로 기록했다.
2. `client/design/product-shell.css`
   - 4개 제품 화면에 공통 브랜드 셸과 최소 44px 조작 영역을 적용했다.
3. 랜딩 페이지
   - 착착이는 질문·힌트, 공식이는 공식 검증·요약을 담당하는 이중 튜터 흐름을 표시했다.
   - 데모 지표에는 샘플 데이터임을 명시했다.
   - 승인된 두 캐릭터 자산만 사용했다.
4. 국제화
   - 8개 필수 로케일의 신규 제품 문구를 40/40 키로 동기화했다.
5. 스테이징 빌드
   - 공통 셸과 승인된 CSS 모션을 포함했다.
   - 사용하지 않는 전체 포즈 묶음과 런타임 모션 JS는 배포에서 제외했다.

## 실패와 수정

- 최초 빌드에서 32개 포즈 PNG/WebP를 모두 복사해 산출물이 약 3.7MB로 증가했고 성능 예산 검사가 실패했다.
- 실제 랜딩은 기존 승인 WebP 2개만 필요하므로 중복 자산 복사를 제거했다.
- 최종 산출물은 35개 파일, 367,992바이트이며 정적 배포 예산 400,000바이트 이내다.
- 예산 상향은 공통 제품 셸·국제화 문구·승인 모션 CSS 추가분을 반영한 것이며, 기존 Lighthouse 증거의 전송량 중앙값은 215,496바이트로 유지된다.
- 통합 테스트 파일을 직접 호출한 보조 명령은 `TEST_SESSION_HMAC_SECRET` 없이 실행되어 3개 파일이 시작 전 차단됐다. 이는 제품 결함이 아니라 하네스 사전 조건 누락이며, 비밀값을 임의 생성하지 않고 격리 환경을 구성하는 정식 명령 `npm.cmd run test:productization:integration`으로 재검증했다.

## 레드팀 결론

P0인 허위 완료 인상, 화면별 디자인 불일치, 작은 조작 영역, 제품 고유 가치의 부재는 로컬 기준선에서 수정됐다. 그러나 이 단계는 AI 기능을 새로 구현한 단계가 아니다. 수학착착의 경쟁력은 다음 Phase에서 `진단 → 소크라테스식 힌트 → 공식 검증 → 오답 원인 태깅 → 다음 문제 추천`을 실제 API·PostgreSQL·안전 정책과 연결해야 비로소 증명된다.

## 다음 Phase 진입 조건

Phase 47은 분수 단원 하나를 대상으로 AI 튜터 커널의 세로 조각을 구현한다. 모델 실패 시 규칙 기반 대체, 정답 직접 노출 방지, 보호자·학생 데이터 분리, 비용·지연 예산, 단위·통합·브라우저 테스트가 모두 필요하다. 운영 배포와 실제 학생 데이터 사용은 별도 승인 전까지 금지한다.
