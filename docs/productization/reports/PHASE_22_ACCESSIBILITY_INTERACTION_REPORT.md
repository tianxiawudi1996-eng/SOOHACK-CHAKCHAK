# 수학착착 Phase 22 키보드·초점·대비·스크린리더 접근성 보고서

## Goal Framing

키보드와 스크린리더를 사용하는 학생·보호자가 네 핵심 화면을 마우스 없이 이동하고, 비동기 학습 전환 뒤에도 현재 위치를 잃지 않도록 개선했다.

## Context Engineering

공통 `interaction.css`와 `interaction.mjs`를 추가해 모든 화면에서 동일한 초점 링, 모션 축소와 건너뛰기 초점 이전을 사용하게 했다. 진단·공식 수업·교육과정 앱에는 화면 상태 전환 뒤 의미 있는 제목으로 초점을 이동하는 로직을 연결했다.

## Harness Engineering

WCAG 상대 휘도 계산기와 12개 핵심 색상 쌍 단위 테스트를 추가했다. 정적 검사기는 양수 tabindex, autofocus, 건너뛰기 대상, 초점 이동 코드, 상태 영역, reduced-motion과 스테이징 복사를 감사한다. 자동 검사는 실제 보조공학 사용자의 승인을 대신하지 않는다.

## Prompt Engineering

기준선에서 초점 소실, 저대비 노란색 초점 링과 작은 보조문구 대비 문제를 식별했다. 모든 본문과 동적 제목을 초점 대상으로 만들고, 진한 청색 3px 링과 흰색 분리선을 적용했다.

## Workflow Engineering

`기준선 감사 → 메타프롬프트·계약 → HTML/CSS/JS 수정 → 대비 단위 검사 → 스테이징 재빌드 → PostgreSQL 통합 검사 → 브라우저 초점 검사 → 수동 검토 패킷 → 보고` 순서로 진행했다.

## Memory Engineering

초점 대상 7개, 대비 조합 12개, 스테이징 해시, 브라우저 검사 결과와 수동 검토 0/1 상태를 남겼다. 브라우저 저장정보, 세션 비밀값, 개인 데이터와 추정 승인은 기록하지 않았다.

## Loop Engineering

진단의 문제·다음 문제·결과, 공식 수업 첫 단계, 교육과정 협업·다음 단계 전환을 반복했다. 각 전환에서 `document.activeElement`와 계산된 초점 링을 확인했으며, 첫 검사에서 드러난 건너뛰기 링크의 브라우저 기본 초점 의존성을 공통 명시적 초점 이전으로 수정했다.
