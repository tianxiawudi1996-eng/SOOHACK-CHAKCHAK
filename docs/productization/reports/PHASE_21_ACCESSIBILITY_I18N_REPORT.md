# 수학착착 Phase 21 접근성 국제화·언어 검토 패킷 자동 검증 보고서

## Goal Framing

학생과 보호자가 선택한 언어로 화면의 보이는 문구뿐 아니라 건너뛰기 링크, 탐색·학습 영역 이름, 이미지 대체텍스트와 진행률 의미까지 일관되게 이해하도록 네 핵심 화면을 보완했다.

## Specification Engineering

- 화면: 랜딩·진단·공식 수업·교육과정 4/4
- 접근성 메시지: 로케일당 31/31, 총 248/248
- 필수 로케일: `ko`, `zh-CN`, `ja`, `en`, `es`, `fr`, `it`, `ru` 8/8
- 비한국어 수동 언어 검토 패킷: 7/7 준비
- 수동 언어 승인: 0/7, 자동 QA와 분리

## Context Engineering

공통 접근성 메시지 모듈을 `client/i18n/accessibility.mjs`에 두고 네 화면의 기존 로케일 결정 흐름에 연결했다. 진단과 공식 수업 진행률에는 `progressbar`, 최소·최대·현재값을 추가했다. 스테이징 빌드는 공통 모듈을 `/i18n/accessibility.mjs`로 배포한다.

## Harness Engineering

키 대칭, 비한국어 한국어 잔존, 런타임 연결, 하드코딩된 접근성 이름, 진행률 의미, 스테이징 복사와 검토 패킷 무결성을 정적 검사했다. 단위 테스트 49개와 PostgreSQL 기반 통합 여정 13개를 통과시켰으며, 수동 검토자의 신원·결정·시각을 추정하지 않았다.

## Prompt Engineering

네 화면의 잔존 영어 접근성 문구를 식별하고 공통 키로 교체했다. 7개 비한국어 언어별로 동일한 네 URL, 검토 체크리스트, 빈 반환 필드와 고정 소스 해시가 포함된 패킷을 생성했다.

## Workflow Engineering

`잔존 문구 감사 → 접근성 키 설계 → 네 화면 런타임 연결 → 진행률 의미 보완 → 검토 패킷 생성 → 정적·단위 검사 → 스테이징 재빌드 → 통합·브라우저 검사 → 보고` 순서로 진행했다.

## Memory Engineering

31개 키와 248개 값, 스테이징 매니페스트 해시, 7개 검토 패킷의 소스 해시와 대기 상태를 남겼다. 검토자 개인정보, 추정 승인, 임시 응답 및 민감한 세션 비밀값은 저장하지 않았다.

## Loop Engineering

중국어 랜딩, 일본어 진단, 프랑스어 공식 수업, 러시아어 교육과정을 실제 브라우저에서 반복 검사했다. 첫 검사에서 발견한 스테이징 랜딩 모듈·번역 JSON 상대경로 오류를 수정하고 재빌드한 뒤 문서 언어·접근성 이름과 콘솔 오류 0건을 재확인했다.
