# 수학착착 국제화·로케일 요구사항 v1.0

## 1. 지원 로케일

| 코드 | 언어 | 1차 범위 | 폰트·표기 유의사항 |
|---|---|---|---|
| `ko` | 한국어 | 원문·한국 시장 | 한국어 줄바꿈, 조사와 존댓말 |
| `zh-CN` | 중국어 간체 | 중국어 사용자 | CJK 폰트, 간결한 버튼 폭 |
| `ja` | 일본어 | 일본어 사용자 | CJK 폰트, 숫자·학년 표기 검토 |
| `en` | 영어 | 전역 fallback | 복수형과 긴 단어 대응 |
| `es` | 스페인어 | 스페인어 사용자 | 성·수 일치와 30% 텍스트 확장 |
| `fr` | 프랑스어 | 프랑스어 사용자 | 구두점 앞 공백과 35% 확장 |
| `it` | 이탈리아어 | 이탈리아어 사용자 | 성·수 일치와 버튼 확장 |
| `ru` | 러시아어 | 러시아어 사용자 | 키릴 문자와 복수형 규칙 |

추가 언어는 번역·교육 용어·시각·접근성·핵심 흐름 QA가 모두 통과한 뒤 `supported_locales`에 추가한다. 중국어 번체와 RTL 언어는 별도 QA 매트릭스를 추가한다.

## 2. 로케일 결정 순서

```text
명시적 URL /{locale}
→ 인증 사용자 설정
→ locale 쿠키
→ Accept-Language
→ en fallback
```

- 사용자가 언어를 명시적으로 바꾸면 선택을 저장하고 같은 경로의 새 로케일 URL로 이동한다.
- IP 주소나 정밀 위치 권한은 언어 결정을 위해 요구하지 않는다.
- 미지원 언어는 가장 가까운 지원 언어 또는 `en`으로 대체한다.
- 검색엔진과 공유 링크가 동일 문서를 식별하도록 로케일 URL을 정규화한다.

## 3. 번역 계약

- 한국어 `ko`는 브랜드·교육 문구의 의미 원본이다.
- 영어 `en`은 런타임 fallback이며 번역 키가 항상 완전해야 한다.
- 키는 `surface.section.intent` 형식을 사용한다. 예: `learning.hint.next_step`.
- 변수·수식·학생 이름을 문장 조각으로 연결하지 않고 ICU 형식의 완전한 문장으로 번역한다.
- HTML을 번역 문자열에 저장하지 않는다.
- 아동용 문구는 번역 후 비난·공포·정답 노출·과도한 유아어 검토를 다시 수행한다.

## 4. 국제화 대상

- UI 문구, 오류, 빈 상태, CTA, 접근성 이름
- SEO 제목·설명·공유 메타데이터
- 숫자, 소수, 백분율, 날짜, 시간, 시간대, 복수형
- 수학 용어, 학년·단원 이름, 수식 주변 설명
- 이메일·알림·학부모 리포트
- 이미지 대체 텍스트와 캐릭터 말풍선

수식 자체의 수학적 의미는 로케일과 무관하게 보존하되 소수점·천 단위 표시와 읽기용 문장은 로케일을 따른다.

## 5. 실패 처리

- 누락 키: `en` fallback + `i18n.missing_key` 진단 이벤트
- 잘못된 URL 로케일: 감지된 지원 로케일로 한 번만 리다이렉트
- 번역 파일 로드 실패: 핵심 UI는 영어로 계속 사용하고 재시도 가능
- 혼합 언어: 자동 검사 실패로 처리
- 사용자 선택과 URL 충돌: URL을 현재 요청의 명시적 선택으로 간주

## 6. QA 매트릭스

각 로케일에서 랜딩 → 진단 → 학습 → 힌트 → 정답/오답 → 완료 → 리포트 흐름을 검사한다.

- 번역 키 누락 0
- 잘림·겹침·가로 스크롤 0
- 키보드 포커스와 화면 읽기 이름 유지
- 360/768/1024/1200px 검증
- 숫자·날짜·복수형 스냅샷
- 한국어·중국어·일본어 줄바꿈과 라틴·키릴 확장 검증
